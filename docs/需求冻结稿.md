# 本地视频刮削器：需求冻结稿

**状态：历史冻结稿（原视频模块需求已完成）**

> 后续新增的视频工坊/漫画书房双模块、漫画 EPUB/PDF 合并及增量追更不属于本冻结稿范围。当前产品能力请以 [模块能力说明.md](模块能力说明.md)、[README.md](../README.md) 与 [AGENTS.md](../AGENTS.md) 为准。

## 1. 交付与技术方向

- 产物：Windows `exe`、macOS `dmg`。
- UI：现代 macOS 风格；Windows/macOS 功能一致。
- 技术：Electron + React + TypeScript；FFmpeg/ffprobe 负责媒体探测、截帧、合并、转码与校验；Sharp 负责图片转 JPG。
- 仓库：GitHub 私有仓库 `king-joker-z/media-scraper-desktop`。
- CI：GitHub Actions 构建 Windows `exe` 与 macOS `dmg`，作为 Actions Artifacts 下载；Release Tag 时附加至 Release。

## 2. 全局规则

1. 用户选择本地工作区目录，默认递归扫描。
2. 支持主流视频与图片格式；以真实容器/编码探测结果为准，不只看扩展名。
3. 五大功能模块完全独立、可单独执行；每个模块均需"扫描→预览→用户确认→执行→报告"。
4. 除视频合并外，统一默认 5 线程，用户可设 1–20；视频合并单独限流。
5. 隐藏文件/隐藏目录完全不处理：不删、不移、不改名、不参与匹配或合并；含隐藏内容的目录不得删除。
6. 普通文件删除均为直接永久删除，不设隔离区、不可恢复；界面必须展示删除清单、数量、体积与原因，用户勾选风险确认后才可执行。无视频、全图删除、大批量删除等危险场景需二次确认/确认词。
7. 重名不覆盖，自动追加 `(1)`、`(2)` 等后缀，并在预览与报告标注。

## 3. 模块一：目录清理、图片匹配与解散子目录

### 保留与删除

- 保留所有视频。
- 每个视频最多保留一张 poster。
- 永久删除：非视频、非图片文件、字幕、旧 NFO、未匹配图片、未被选为 poster 的候选图片。
- 功能完成后，将保留视频和 poster 上移到工作区根目录；仅删除已清空且不含隐藏内容的子目录。

### 图片匹配

- 仅同层目录匹配，不跨目录。
- 忽略扩展名、大小写、空格、`-`、`_`、`.`；识别并忽略 `-poster` 后缀。
- 不默认清除年份、分辨率、版本、CD 分段等语义片段。
- 一个视频有多张候选图：`-poster` 图优先 → 与视频名完全同名图次之 → 仍冲突时标红并由用户手选；选中图转 JPG，命名为 `<视频基名>-poster.jpg`；其余候选永久删除。
- 一张图可匹配多个视频：判为歧义，图片不保留、直接永久删除；相关视频标记无 poster。

### 执行顺序

扫描→关联计算→处理候选冲突→生成删除/上移计划→确认永久删除→删除→上移保留文件→解决重名→删除空目录→报告。

## 4. 模块二：视频物理合并

- 展示视频缩略图、标题、路径、时长、大小、分辨率、方向、真实容器、视频/音频编码、帧率。
- 支持：全合并、横屏合并、竖屏合并、自由组合（多选、拖拽排序）。
- 输出名使用工作区目录名：
  - `<工作区名>-merged.mp4`
  - `<工作区名>-landscape-merged.mp4`
  - `<工作区名>-portrait-merged.mp4`
  - `<工作区名>-custom-merged.mp4`
- 兼容素材优先无重编码拼接；不兼容素材转换为统一兼容参数后再合并。
- 合并前展示兼容结论、预计大小、可用空间、是否转码；合并后校验可读取、时长、音视频流。
- 校验成功后，永久删除本次参与合并的源视频与关联 poster；未参与视频不删除。删除源片段必须在计划中单独展示和确认。

## 5. 模块三：批量重命名

- 视频和 poster 作为一组处理。
- 所有改名先展示可编辑预览；校验非法字符、空名、超长路径、大小写冲突与重名。
- 视频改名后 poster 同步改为 `<新视频基名>-poster.jpg`。
- 支持：纯序号（标题/大小，升降序，位数与分隔符可设）、正则清洗+序号（规则可测试和保存）、AI 重命名。
- AI：通过 OpenRouter 配置 Token/模型；仅发送用户允许的文件名、目录名与 Prompt，不上传视频；支持变量 `{{parentFolder}}`、`{{fileName}}`、`{{extension}}`；结果通过结构/冲突校验后仍须用户确认。
- 另提供"仅改扩展名为 `.mp4`（不转换媒体）"：不转码、不重封装；真实容器非 MP4 时显著提示风险并单独确认；合并逻辑始终按真实媒体探测结果判定。

## 6. 模块四：Poster 封面管理

- 有现存匹配 poster 时默认显示；无 poster 时每个视频默认截取 5 张候选图（10%、30%、50%、70%、90%）。
- 详情页可查看候选、播放视频、拖动时间轴、指定时点截图。
- 保存时选定唯一封面，转 JPG，命名为 `<当前视频基名>-poster.jpg`。
- 同视频其他候选或旧关联图列入永久删除清单，确认后删除。

## 7. 模块五：NFO 与独立归档

- 默认归档路径：`<工作区根目录>/<视频基名>/`；也支持用户指定外部输出目录。
- 顺序：选择视频与 poster → 建独立目录 → 移入视频和 poster → 在归档目录内生成 NFO → 校验 XML 与文件关系。
- 不按演员、类型、日期等继续分层。
- NFO 兼容 Kodi/Jellyfin/Emby；基础字段，不联网：

```xml
<?xml version="1.0" encoding="utf-8" standalone="yes"?>
<movie>
  <title>视频文件名</title>
  <poster>视频文件名-poster.jpg</poster>
  <actor>
    <name>工作区文件夹名</name>
    <role>工作区文件夹名</role>
    <type>Actor</type>
  </actor>
</movie>
```

- `actor.name` 与 `actor.role` 均取工作区文件夹名，非归档子目录名。

## 8. 工程阶段与质量门禁

1. 工程骨架：Electron+React、macOS 风格 UI、目录选择、扫描、媒体探测、任务中心、GitHub Actions。
2. 文件整理与封面：清理、匹配、解散、重名、poster 转 JPG、截帧、永久删除确认。
3. 重命名、归档、NFO：序号、正则、AI、仅改 `.mp4` 扩展名、独立归档、基础 NFO。
4. 视频合并：无重编码拼接、兼容转码合并、输出校验、源片段删除确认。
5. 测试/CR/发布：自动化测试、真实样本测试、双端打包验证、测试鸟 CR、缺陷清零或用户确认后提交 PR/发布。
