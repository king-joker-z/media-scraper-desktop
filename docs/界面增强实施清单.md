# 界面增强实施清单

> 范围：任务动态岛、视频合并时间线拼贴台、批量重命名前后对照编辑器、封面接触表与视觉相似浏览、可回放操作时间线。
>
> 目标：让本地媒体整理过程具备可见的状态、可解释的决策和高效的键盘/鼠标操作；不以装饰性动画牺牲批量任务、文件安全和跨平台稳定性。
>
> 非目标：不替换现有主题系统，不引入整套 Fluent / Material / shadcn UI，不改变主进程文件操作、TaskCenter 取消语义或 `media://` 白名单模型。

## 1. 当前基线与实施原则

### 1.1 已可复用的能力

| 能力                       | 现有位置                                                          | 本计划中的用途                                       |
| -------------------------- | ----------------------------------------------------------------- | ---------------------------------------------------- |
| 任务事件、取消、节流广播   | `src/main/core/task-center.mjs`、`src/main/index.ts`              | 动态岛、队列状态、完成摘要、失败入口                 |
| 全局任务进度与任务抽屉     | `src/renderer/src/components/TaskProgress.tsx`、`TaskCenter.tsx`  | 保留数据逻辑，拆分展示壳层                           |
| 片段拖拽排序               | `src/renderer/src/components/MergeSortableList.tsx`、`@dnd-kit/*` | 时间线排序和列表/时间线双视图                        |
| 视频预览及 Range 流式加载  | `VideoModal.tsx`、`mediaUrl()`、`media://`                        | 合并片段预览、封面接触表视频定位                     |
| 截帧候选与质量评分         | `PosterPage.tsx`、`PosterDetail.tsx`、`CandidateFrameScore`       | 接触表、质量排序、视觉相似分组                       |
| 两段式安全重命名、冲突校验 | `modules/rename/execute.mjs`、`rename-rules.mjs`                  | 重命名过程解释、冲突关系展示                         |
| 本地操作日志与一键撤销     | `core/op-log.mjs`、`OpLogPanel.tsx`                               | 时间线、详情、撤销预检与恢复结果                     |
| 主题、色板、降低动态效果   | `main.css`、`SettingsPage.tsx`                                    | 所有新组件遵守统一 token 和 `prefers-reduced-motion` |

### 1.2 共同约束

- 所有媒体文件访问继续走 `mediaUrl()`，不得将本地绝对路径直接放入 `src` 或 CSS `url()`。
- 新增跨进程数据时严格走：`src/shared/types.ts` -> `src/main/index.ts` 的 `ipcMain.handle` -> `src/preload/index.ts` -> `src/preload/index.d.ts`。
- 新的批量任务继续接入 `TaskCenter`，不在渲染端自行建立并发队列。
- 文件改名、移动、删除、写封面仍只走既有 `fs-ops.mjs` 和业务模块，不因 UI 升级绕开安全替换、锁重试、日志与撤销。
- 动画只使用 `transform`、`opacity`、有限范围的 `clip-path`；不循环动画大量缩略图，不在 React state 中逐帧写入鼠标或滚动坐标。
- 每个交互均有鼠标、键盘和屏幕阅读器路径；危险操作不因视觉升级绕开 `ConfirmDialog`。

## 2. 组件库与依赖决策

### 2.1 采用策略

现有项目使用 React + 原生 CSS，且拥有丰富主题覆盖。组件库只引入“行为层”能力，所有视觉样式继续由项目 CSS token 和主题规则控制。

| 类别       | 选择                                                                                                           | 状态     | 用途                                              | 决策理由                                               |
| ---------- | -------------------------------------------------------------------------------------------------------------- | -------- | ------------------------------------------------- | ------------------------------------------------------ |
| 排序拖拽   | `@dnd-kit/core`、`@dnd-kit/sortable`、`@dnd-kit/utilities`                                                     | 已安装   | 合并时间线重排、键盘排序                          | 已在 `MergeSortableList` 稳定使用，无需重复选型        |
| 动画       | `motion`                                                                                                       | 已安装   | 动态岛形态切换、时间线/详情共享元素、卡片布局动画 | 可按组件懒加载，能处理 layout 动画与降低动态效果       |
| 无障碍浮层 | `@radix-ui/react-dialog`、`@radix-ui/react-popover`、`@radix-ui/react-tooltip`、`@radix-ui/react-context-menu` | 已安装   | 检查器、详情浮层、右键菜单、提示                  | 只提供焦点管理、ARIA 和定位，不接管主题                |
| 可调整面板 | `react-resizable-panels`                                                                                       | 已安装   | 合并页“列表/时间线/检查器”三栏布局                | 对桌面端鼠标、键盘和窗口尺寸变化更稳，不手写拖拽分割线 |
| 虚拟列表   | 优先复用 `VirtualGrid`；必要时再评估 `@tanstack/react-virtual`                                                 | 暂不新增 | 大量封面候选、日志详情、媒体片段                  | 避免引入重复能力，先测量现有组件在大目录的表现         |
| 图形关系图 | 原生 SVG + CSS                                                                                                 | 暂不新增 | 重命名冲突连线、操作前后关系                      | 图数据有限，避免为一个局部图引入重量级图编辑器         |

### 2.2 安装清单

- [x] 已安装 Motion、Radix 浮层组件与可调整面板依赖，并已同步更新 `package.json`、`package-lock.json`。
- [x] 已执行 `npm run typecheck` 与 `npm run lint`，均通过。

实际执行的安装命令：

```bash
npm install motion @radix-ui/react-dialog @radix-ui/react-popover @radix-ui/react-tooltip @radix-ui/react-context-menu react-resizable-panels
```

不引入的库：

- 不引入 `@fluentui/react-components`：视觉和 token 体系会与现有多主题 CSS 发生大范围冲突；仅借鉴其 Windows 桌面交互密度。
- 不引入完整 `@adobe/react-spectrum`：体积和样式策略对当前项目过重；仅参考 React Aria 的键盘操作思路。
- 不引入 Tailwind、shadcn/ui、Magic UI：项目当前不是 Tailwind 栈，迁移成本和视觉割裂大于收益。
- 不引入 Three.js、Canvas 粒子或全局 WebGL 背景：与本地媒体处理同时运行时会增加 GPU 压力，且不服务核心任务。

## 10. 完成定义

五项增强完成后，用户应能：

- 在任何页面看见真实任务状态、失败原因和结果入口，并用键盘快速打开任务队列。
- 在合并前通过时间线理解片段顺序、总时长、参数差异、转码原因与最终输出规格。
- 在执行重命名前理解每个文件为何变成目标名，能高效处理冲突和手动覆写。
- 在封面选择中按时间、质量和相似度快速找到合适帧，并能通过键盘确认保存。
- 在历史中回看文件变更，查看受影响项，并在允许的场景下经过预检后安全撤销。

所有上述能力必须在浅色、深色和现有主题色板中保持可读性，且不牺牲 Windows 文件锁处理、macOS/Windows 快捷键、取消语义、`media://` 安全范围及既有测试基线。
