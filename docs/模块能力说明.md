# 模块能力说明

> 本文档逐模块说明 Media Scraper Desktop 的能力、实现位置、数据流与规则边界。
> 对应源码以 `src/main/modules/`（主进程业务）、`src/renderer/src/pages/`（界面）、`src/shared/`（共享规则）为准。

## 一、目录清理（CleanPage）

**能力**：扫描工作区，生成「保留 / 删除 / 上移 / 待人工选择」的只读计划，用户确认后执行。

### 扫描规则（`core/scanner.mjs`）

- 递归遍历工作区，隐藏项（`.` 开头、`@eaDir`、`#recycle` 等）整体跳过并计入 `skippedHidden`。
- 文件分类：`VIDEO_EXTENSIONS` / `IMAGE_EXTENSIONS` / 其他（`classifyPath`）。
- **图片-视频配对**：同目录下按标准化基名（`normalizedName`，大小写/分隔符归一）匹配。
  - 一图对一视频 → 保留，统一标准化为 `<视频基名>-poster.jpg`（`posterFinalName`，预览与执行同名）；
  - 一视频多图且无法裁决 → 进 `pendingPick`，执行前由用户人工选择（`PosterPicks`）；
  - 一图对多视频 → 冲突（`image-multi-video`），不自动处理；
  - 无匹配图片 → 删除候选；`.nfo`、字幕等其他文件按规则归入删除候选。
- **上移预测**（`predictMoves`）：子目录中的视频预测上移到根目录，重名预测追加 ` (n)` 后缀并在预览中标注。
- **风险评估**（`assessRisk`）：删除项 > 50、体积 > 1GB、或工作区无视频 → `risk: 'danger'`，执行前要求输入确认词二次确认。

### 执行（`modules/clean/execute.mjs`）

`executeCleanPlan(plan, { picks, taskCenter, taskId, concurrency, deleteFn })`：

1. 删除清理项（默认经 `shell.trashItem` 移入系统回收站，设置页可改永久删除；`deleteFn` 由主进程按设置注入，Windows 瞬态文件锁由 `withLockRetry` 重试兜底）；
2. 子目录视频上移（`moveWithCollision` 自动处理重名）；
3. 非 JPG 封面经 `sharp` 转码为 JPG（`core/image.mjs`），封面统一改名 `-poster.jpg`；
4. 清理空目录（`removeEmptyDirs`，顺带识别 `.DS_Store`、`Thumbs.db` 等垃圾文件名 `isJunkFileName`）；
5. 产出 `CleanReport`（删除数/体积、转码、改名、上移、移除目录、失败项、耗时），并写操作日志。

全程接入 TaskCenter：并发可调、可取消、进度实时上报。

## 二、漫画合并与漫画库（ComicMergePage / ComicLibraryPage）

**工作区模型**：漫画工作区的一级子目录是一部漫画；漫画目录的一级子目录是章节，目录内直接存在的图片归入排在最前的虚拟章节「正篇」。隐藏文件/目录跳过。章节与图片使用 `localeCompare('zh-Hans-CN', { numeric: true })` 自然排序。

### 扫描与状态（`modules/comic/scan.mjs`）

- 支持 `.jpg` / `.jpeg` / `.png` / `.webp` / `.gif` / `.bmp` / `.avif`。
- 每部漫画的 `.comic-merge.json` 保存格式、产物名、大小及已合并章节图片快照；隐藏封面 `.comic-cover.jpg` 在源图删除后仍供漫画库显示。
- 对比当前扫描与快照：仅出现新章节时可增量追加；已合并章节的图片增删或排序变化标记为变更，禁止直接追加。

### 合并与图片策略（`modules/comic/merge.mjs`）

1. 用户从漫画合并页选择 EPUB 或 PDF、原样模式与全量重建；每部漫画是一个 TaskCenter 条目，可并发、可取消并显示全局进度。
2. 默认优化模式：超过 1600px 宽的图片缩放至 1600px，透明图铺白底，转 mozjpeg q85；兼顾阅读质量与体积。
3. 原样模式：EPUB 仅读取图片元数据后由 ZIP 写入器按文件路径流式收录原图；PDF 对 JPG/PNG 直接嵌入，其他格式仍以 JPEG q92 转码。
4. EPUB 使用 `yazl` 流式创建：一图一页 fixed-layout XHTML、章节 `nav.xhtml`、OPF manifest/spine；图片采用 STORE，避免重复压缩。每次仅保留当前图片与 ZIP 缓冲，适用于数千页漫画。PDF 使用 `pdf-lib`，每图对应一页并按图片尺寸建页，但其保存模型仍需整本序列化。
5. 有同格式产物且只有新章节时，EPUB 由 `yauzl` 逐条目读取旧书、跳过旧 OPF/nav 后流式复制旧页面，再续编新章节；不会整书解压到内存，也不会重新转码旧图。PDF 在既有文档末尾追加页面但会重写整份文件。切换 EPUB/PDF、修改旧章节、或需要重新套用压缩策略时必须勾选「全量重建」。
6. EPUB 单本内顺序处理图片；批量时 EPUB 最多并行 2 本，PDF 强制单本，以降低 Windows 上磁盘、内存竞争。
7. 产物先写入同目录 `.msd-new-<uuid>` 暂存文件；EPUB 需通过关键 entry 与页数结构校验，才会将旧产物暂移到 `.msd-backup-<uuid>` 并落位新文件。Windows 短暂文件锁由 `fs-ops` 重试处理；失败优先恢复旧产物，扫描时 `recoverStagedOutputs()` 会恢复断电遗留备份。清单只在产物提交成功后写入。

### 删除源图与漫画库

- 合并报告确认后可删除**清单已覆盖**的源图片，默认进入系统回收站；只删除图片，不删除 EPUB/PDF、清单和隐藏封面，并清理空章节目录。
- 删源后继续下载的新章节仍可增量追加，旧章节继续由已合并产物保留。
- 漫画库以卡片展示隐藏封面、名称、格式和产物大小，支持搜索、打开产物、在文件管理器定位，并可跳回合并页处理追更。

## 三、视频合并（MergePage）

**能力**：把工作区内多个片段合并为单个 MP4，支持横屏/竖屏筛选、拖拽排序、单段排除、兼容性预判、断点续传、合并后删除源文件。

### 流程

1. **扫描**（`merge:scan`）：列出视频（排除 `isMergeOutputName` 匹配的本产品合并产物），逐段 `probeMediaCached` 读取容器/时长/分辨率/编码/帧率/像素格式/音频参数，并读取磁盘剩余空间。
2. **模式**：`all`（全部）/ `landscape`（横屏）/ `portrait`（竖屏）。片段列表支持 @dnd-kit 拖拽排序（`MergeSortableList`）与单段置灰排除。
3. **兼容性判定**（`shared/merge-rules.mjs`）：编码、分辨率、帧率、像素格式、采样率、声道一致 → **无重编码 concat 拼接**（极快）；不一致 → 以首个片段为目标参数**逐段转码统一后合并**，UI 展示不兼容原因与预计输出体积（`estimateMergedBytes`，按最大码率×总时长估算）。
4. **输出命名**：`<工作区目录名>[-landscape|-portrait]-merged.mp4`（`mergeOutputName`），重名自动 ` (n)`。
5. **执行**（`modules/merge/merge.mjs` → `mergeVideos`）：
   - 转码模式：每段转到工作目录（`mergeWorkDir`，按片段集合+目标参数哈希命名），**断点续传**——已就绪的中间段跳过；就绪判定校验「存在 + 可读 + 时长与源一致（±1s）」，截断段强制重转；
   - 拼接用 ffmpeg concat demuxer（`buildConcatList` 转义单引号）；
   - 产出前**输出校验**：ffprobe 复查时长与各段总时长一致性，`verified`/`verifyNote` 回报；
   - 取消（AbortController）：在途 ffmpeg 被杀，工作目录保留以便续传。
6. **删除源文件**：仅在 `verified && !cancelled` 后弹确认框（`ConfirmDialog`），可选「同时删除关联封面」，经 `deleteMergeSources` 批量删除并写日志。

### 进度

合并不走 TaskCenter 的条目模型，直接以 0–100 百分比 + 阶段描述上报（准备 → 转码各段 → 拼接 → 校验）。

## 四、批量重命名（RenamePage）

**能力**：四种模式批量改名，封面随视频联动改名，全程预览可编辑、可单条 AI 重生成。

### 四种模式

| 模式             | 逻辑                                                                     |
| ---------------- | ------------------------------------------------------------------------ |
| 纯序号 `seq`     | 剥离旧序号前缀（`stripSeqPrefix`，幂等）后按排序重新编号                 |
| 正则清洗 `regex` | 套用预设/自定义正则模板（`applyRegexRules`，非法规则跳过）后叠加序号前缀 |
| AI 命名 `ai`     | AI 返回词干（剥离可能带回的前缀）后叠加序号前缀；支持对单条重新生成      |
| 仅改扩展名 `ext` | 词干不动，仅把扩展名统一为 `.mp4`                                        |

### 序号体系（`shared/rename-rules.mjs`）

- `SeqOptions`：`sortBy`（标题/大小，数字感知排序 `compareTitles`）、`order`（正/倒序）、`digits`（补零位数）、`separator`（分隔符）、**`start`（起始序号，1–9999，默认 1）**。
- 起始序号用于续批场景：已有 `01–50` 的批次，新数据从 51 起编。`buildSequenceStems` / `withSequencePrefix` 均接受 `start`。
- `stripSeqPrefix`：连续剥离 `01.`、`01.02.`、`03 - `、`003_`、`0001.` 等叠层前缀；**保护年份**（`2024 演唱会` 不被误剥）。

### 校验与执行

- `validateStems`：非法字符（含 ASCII 控制字符）、**Windows 保留设备名**（CON/PRN/AUX/NUL/COM1-9/LPT1-9，`WINDOWS_RESERVED_NAME_RE`）、**末尾点号/空格**（Windows 会自动截断，`TRAILING_DOT_SPACE_RE`）、空名、超长（>200）、重名（大小写不敏感）逐条标红，存在错误禁止执行。
- 真实容器探测（`rename:probe` → ffprobe）：识别「伪 MP4」，配合仅改扩展名模式使用。
- 执行（`modules/rename/execute.mjs`）：**两段式改名**（先临时名后目标名）规避交换冲突；封面（`posterRel`）与视频联动改名；产出 `RenameReport` 并写日志。

### AI 命名（`modules/rename/ai.mjs`）

- OpenAI 兼容端点（`chat/completions`），多平台配置（预设 openrouter / deepseek / aicodemirror + 自定义），**token 按平台独立持久化**，模型下拉可切换。
- 批处理（`AI_BATCH_SIZE` = 20 一批）、**批间限流并发**（`AI_BATCH_CONCURRENCY` = 2，429 由 `fetchWithRetry` 指数退避兜底）、prompt 模板变量 `{{parentFolder}} {{fileName}} {{extension}}`（`buildPrompt`）、**LRU 有界结果缓存**（按平台端点 + 模型 + 模板 + 文件区分，相同输入不重复请求）。
- system prompt 内置 Windows 命名约束（禁保留设备名/尾点空格/非法字符）与严格数组输出契约，从源头减少不可执行的返回。
- 响应解析 `extractJsonArray` 兼容代码块、包装对象、前后说明文本与常见 OpenAI/SSE 响应形态；单条重新生成在模型直接给出纯文本标题时安全降级接受，批量仍严格校验返回数量。
- AI 生成过程接入全局进度条（按批次上报）。

## 五、封面管理（PosterPage）

**能力**：批量为视频生成/更换封面，卡片网格展示，支持逐片精选帧与批量保存。

### 流程

1. **列表**（`poster:list` → `listPosterVideos`）：视频及其现存 poster。
2. **候选帧**（`poster:capture` → `captureCandidates`）：对每个视频取多张候选帧——时间均布采样（`buildFrameTimestamps`）+ **场景切分检测**（`detectSceneCuts`，ffmpeg scdet，挑画面变化大的帧），帧存临时目录（`framesRoot`），经 TaskCenter 并发截取。
3. **精选**（`PosterDetail` 组件）：逐片查看候选帧大图；支持输入任意秒数定点补截（`poster:capture-at` → `captureAt`）；选定帧作为该视频候选封面。
4. **保存**（`poster:save` / `poster:save-batch`）：选中帧复制为 `<视频基名>-poster.jpg`（sharp 转 JPG），同路径覆盖写并删除旧 poster；批量保存先经 `computePendingSaves` 算出待保存集（跳过未变更项），二次确认后执行。
5. **缓存处理**：协议层图片 `no-store` + 渲染端 URL 版本参数，保证覆盖写后界面立即显示新图；`cleanupFrames` 清理临时帧。

## 六、NFO 归档（NfoPage）

**能力**：把散乱视频按「一片一目录」归档，生成 Emby/Jellyfin 兼容的 `.nfo` 元数据。

- **计划**（`createNfoPlan`）：每个视频 → 目标目录（以词干命名，相对工作区根），关联 poster 一并纳入；目标目录已存在且非空标记 `conflict`；从目录结构推断默认演员名 `actorDefault`。
- **执行**（`executeNfoPlan`）：建目录（`ensureDir`）→ 移动视频与 poster → 写入 `movie.nfo`（`renderNfoXml`：`title`/`poster`/`actor`，XML 转义 `escapeXml`）→ 清理空目录。冲突项在 UI 提示由用户确认策略。
- 产出 `NfoReport`（归档数、失败项、耗时）并写日志。

## 七、视频去重（DedupePage）

**能力**：找出重复视频（完全重复 + 相似重复），按组展示，勾选删除。

- **完全重复**（exact）：先按文件大小分组，同大小再计算**采样哈希**（`hashFileSample`，头/中/尾采样 MD5，避免全量读大文件），同哈希归为一组；组内按探测质量（分辨率/时长/码率）给出**建议保留**项，默认勾选其余副本。
- **相似重复**（similar）：同片不同压制版本——同分辨率 + 时长容差 ±0.5s（`SIMILAR_DURATION_TOLERANCE_MS`）+ 组内体积差 ≥ 10%（`SIMILAR_SIZE_RATIO_MIN`）聚类；建议保留体积最大者（≈码率最高）。
- **快速模式**：`includeSimilar: false` 时跳过全量 ffprobe 与相似聚类（完全重复只需大小+采样哈希），大工作区首扫从分钟级降到秒级；UI 有「快速模式」开关。
- **删除**：确认后经 TaskCenter 批量删除（默认进回收站），产出删除报告并写日志；UI 实时显示勾选可释放的体积，支持对比预览（`VideoModal`）。

## 八、媒体库（LibraryPage）

**能力**：只读浏览工作区——卡片网格（封面 + 标题 + 大小）、搜索过滤、点击播放。

- 数据源复用 `poster:list`；封面缺失显示占位。
- 播放经 `VideoModal`：`media://` 流式加载（支持 Range 拖动），**记忆播放进度**，再次打开续播。

## 九、设置（SettingsPage）

持久化于 `userData/settings.json`（`core/settings.mjs`，`normalizeSettings` 负责旧版本配置迁移）：

- **并发线程数**：1–20，默认 5（`clampConcurrency`），作用于除视频合并外的全部批量任务；
- **扫描子目录并发**：1–16，默认 4（`scanConcurrency`，大目录树加速遍历）；
- **FFmpeg 进程池**：1–8，默认 4（`ffmpegPoolSize`，限制同时运行的媒体处理子进程数，运行时生效）；
- **界面主题**：浅色 / 深色 / 跟随系统（`theme`）；
- **删除方式**：默认移入系统回收站（`deleteToTrash`，误删可恢复），可改永久删除；
- **AI 平台**：多平台配置（预设 + 自定义），各自独立保存 baseUrl / token / 模型列表 / 当前模型，切换平台不清除 token；
- **Prompt 模板**：AI 命名模板，支持 `{{parentFolder}} {{fileName}} {{extension}}`；
- **正则模板**：重命名清洗规则预设（名称 + pattern + replacement + flags），可增删；
- **最近工作区**：视频和漫画各自最多保存 8 个（`recentWorkspaces` / `comicRecentWorkspaces`），支持拖拽导入与快速切换；漫画默认格式 `comicFormat` 单独持久化；
- **存储管理**：展示截帧缓存 / 合并断点续传工作目录 / 操作日志占用，可分类清理（`storage:stats` / `storage:clean`）；
- **自动更新**：基于 GitHub Releases 检查 / 下载 / 安装（`update:*` 频道，状态经 `update:status` 广播）。

设置输入做防抖保存（连续操作清除上一个定时器，提示停留时间从最后一次操作起算）；渲染端改动即写即读。

## 基础设施

### TaskCenter（`core/task-center.mjs`）

统一并发调度：`run({ taskId, label, items, worker, concurrency })` 逐项派发，`worker` 收 `AbortSignal`；`cancel(taskId)` 停止派发并通知在途。每项产出 `TaskEvent`，主进程 120ms 节流后广播 `tasks:event`；渲染端 `TaskProgress`（右下角全局进度条）与 `TaskCenter`（任务抽屉，历史任务列表）订阅。

### 页面状态与自动重扫（`useWorkspaceSync`）

- 视频模块页面常驻挂载，切换仅显隐，状态（扫描结果、报告、排序、编辑内容）完整保留；漫画模块同样保留合并/库页面状态；每页独立 `ErrorBoundary` 隔离崩溃。
- 页面变为可见或工作区切换时，对比 `computeFingerprint(root)`（递归文件 `相对路径:大小:mtime` 排序后的 MD5，隐藏项不计）：
  - 指纹不变 → 直接展示缓存结果；
  - 指纹变化 → 自动调用该页扫描函数；
  - 指纹计算失败（目录被删等）→ 静默保留原状。

### media:// 协议（`src/main/index.ts` + `core/media-path.mjs`）

渲染端访问本地媒体的唯一通道。只允许已选的视频工作区、漫画工作区与截帧临时目录（越界 403）；透传 Range（视频进度条）；图片强制 `Cache-Control: no-store`。渲染端经 `mediaUrl()` 生成 URL。

路径还原与白名单归一化统一在 `core/media-path.mjs`（纯函数可单测）：`mediaUrlPathToLocal`（盘符去前导斜杠、UNC 保留双斜杠、`resolve` 归一化 `..` 防路径穿越）、`normalizeMediaPath`（正斜杠统一、盘符大写、去尾部分隔符）、`isMediaPathAllowed`（精确匹配或前缀+分隔符，防 `C:/ws` 误配 `C:/ws2`）。

### 操作日志与撤销（`core/op-log.mjs` + `modules/undo/undo.mjs`）

清理 / 重命名 / NFO 归档 / 合并删源 / 去重删除 完成后写 JSON（含模块、时间、参数、报告、一句话摘要）到 `userData/op-logs/`；`OpLogPanel` 倒序展示（并行批量读取），`op-logs:reveal` 在系统文件管理器中定位。写日志失败不影响主流程。

**一键撤销**（`op-logs:undo`）：重命名 / NFO 归档类日志可按记录反向恢复（重命名把新名移回原路径、归档把视频/poster 移回根目录并删除 NFO 与空目录）；成功全部回退后日志标记 `undoneAt`，重复撤销被拒绝；删除类日志不支持撤销（`undoable` 标记）。

### 文件操作（`core/fs-ops.mjs`）

全部写操作唯一入口：`permanentDelete`、`ensureUniquePath`（重名 ` (n)`，上限 9999 防死循环）、`moveWithCollision`（跨盘自动 copy+删源，缓冲区 4MB）、`renameWithCollision`、`directRename`、`writeTextFile`、`writeBinaryFile` / `writeAtomicTextFile`（同目录暂存后安全替换）、`writeReadableFile`（大文件流式写入）、`commitStagedFile` / `recoverStagedOutputs`（备份提交与崩溃恢复）、`readBinaryFile`、`removeEmptyDirs`（含垃圾文件识别）、`ensureDir`、`diskFreeBytes`、`dirSizeBytes`（子目录并发遍历，车道数 8）。删除/移动/安全替换经 `withLockRetry` 重试，容忍 Windows 杀软/索引器的瞬态文件锁。

### 媒体探测（`core/probe.mjs`）

`probeMedia` 解析 ffprobe JSON 为 `MediaInfo`（容器/时长/分辨率/方向/编码/帧率/像素格式/音频参数）；`probeMediaCached` 按 路径+mtime 缓存（LRU 有界），重复扫描免探测。

### 子进程治理（`core/ffmpeg-pool.mjs` + `core/process-registry.mjs`）

- 所有 ffmpeg/ffprobe 子进程经 `runPooled`/`spawnPooled` 受池控（1–8，默认 4），防大批量任务同时起几十个进程打满 CPU/内存；`setPoolSize` 运行时调整。
- `trackChild` 统一登记子进程：取消/退出时 POSIX 发 SIGTERM、Windows 向 stdin 写 `q`（ffmpeg 优雅退出，来得及写 mp4 moov），宽限期后兜底 SIGKILL；应用 `before-quit` 轮询等活跃进程归零（上限 3s）再强杀残留，防孤儿进程。
