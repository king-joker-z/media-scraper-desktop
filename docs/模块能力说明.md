# 模块能力说明

> 本文档逐模块说明 Media Scraper Desktop 的能力、实现位置、数据流与规则边界。
> 对应源码以 `src/main/modules/`（主进程业务）、`src/renderer/src/pages/`（界面）、`src/shared/`（共享规则）为准。

## 一、目录清理（CleanPage）

**能力**：扫描工作区，生成「保留 / 删除 / 上移 / 待人工选择」的只读计划，用户确认后执行。

### 扫描规则（`core/scanner.mjs`）

- 递归遍历工作区，隐藏项（`.` 开头、`@eaDir`、`#recycle` 等）整体跳过并计入 `skippedHidden`。
- 文件分类：`VIDEO_EXTENSIONS` / `IMAGE_EXTENSIONS` / 其他（`classifyPath`）。
- **图片-视频配对**：同目录下按标准化基名（`normalizedName`，大小写/分隔符归一）匹配。
  - 一图对一视频 → 保留，统一标准化为 `<视频基名>-poster.jpg`（`posterFinalName`，预览与执行同名）；
  - 一视频多图且无法裁决 → 进 `pendingPick`，执行前由用户人工选择（`PosterPicks`）；
  - 一图对多视频 → 冲突（`image-multi-video`），不自动处理；
  - 无匹配图片 → 删除候选；`.nfo`、字幕等其他文件按规则归入删除候选。
- **上移预测**（`predictMoves`）：子目录中的视频预测上移到根目录，重名预测追加 ` (n)` 后缀并在预览中标注。
- **风险评估**（`assessRisk`）：删除项 > 50、体积 > 1GB、或工作区无视频 → `risk: 'danger'`，执行前要求输入确认词二次确认。

### 执行（`modules/clean/execute.mjs`）

`executeCleanPlan(plan, { picks, taskCenter, taskId, concurrency })`：

1. 永久删除（`permanentDelete`，不进回收站——UI 有明确警示）；
2. 子目录视频上移（`moveWithCollision` 自动处理重名）；
3. 非 JPG 封面经 `sharp` 转码为 JPG（`core/image.mjs`），封面统一改名 `-poster.jpg`；
4. 清理空目录（`removeEmptyDirs`，顺带识别 `.DS_Store`、`Thumbs.db` 等垃圾文件名 `isJunkFileName`）；
5. 产出 `CleanReport`（删除数/体积、转码、改名、上移、移除目录、失败项、耗时），并写操作日志。

全程接入 TaskCenter：并发可调、可取消、进度实时上报。

## 二、视频合并（MergePage）

**能力**：把工作区内多个片段合并为单个 MP4，支持横屏/竖屏筛选、拖拽排序、单段排除、兼容性预判、断点续传、合并后删除源文件。

### 流程

1. **扫描**（`merge:scan`）：列出视频（排除 `isMergeOutputName` 匹配的本产品合并产物），逐段 `probeMediaCached` 读取容器/时长/分辨率/编码/帧率/像素格式/音频参数，并读取磁盘剩余空间。
2. **模式**：`all`（全部）/ `landscape`（横屏）/ `portrait`（竖屏）。片段列表支持 @dnd-kit 拖拽排序（`MergeSortableList`）与单段置灰排除。
3. **兼容性判定**（`shared/merge-rules.mjs`）：编码、分辨率、帧率、像素格式、采样率、声道一致 → **无重编码 concat 拼接**（极快）；不一致 → 以首个片段为目标参数**逐段转码统一后合并**，UI 展示不兼容原因与预计输出体积（`estimateMergedBytes`，按最大码率×总时长估算）。
4. **输出命名**：`<工作区目录名>[-landscape|-portrait]-merged.mp4`（`mergeOutputName`），重名自动 ` (n)`。
5. **执行**（`modules/merge/merge.mjs` → `mergeVideos`）：
   - 转码模式：每段转到工作目录（`mergeWorkDir`，按片段集合+目标参数哈希命名），**断点续传**——已就绪的中间段跳过；就绪判定校验「存在 + 可读 + 时长与源一致（±1s）」，截断段强制重转；
   - 拼接用 ffmpeg concat demuxer（`buildConcatList` 转义单引号）；
   - 产出前**输出校验**：ffprobe 复查时长与各段总时长一致性，`verified`/`verifyNote` 回报；
   - 取消（AbortController）：在途 ffmpeg 被杀，工作目录保留以便续传。
6. **删除源文件**：仅在 `verified && !cancelled` 后弹确认框（`ConfirmDialog`），可选「同时删除关联封面」，经 `deleteMergeSources` 批量删除并写日志。

### 进度

合并不走 TaskCenter 的条目模型，直接以 0–100 百分比 + 阶段描述上报（准备 → 转码各段 → 拼接 → 校验）。

## 三、批量重命名（RenamePage）

**能力**：四种模式批量改名，封面随视频联动改名，全程预览可编辑、可单条 AI 重生成。

### 四种模式

| 模式             | 逻辑                                                                     |
| ---------------- | ------------------------------------------------------------------------ |
| 纯序号 `seq`     | 剥离旧序号前缀（`stripSeqPrefix`，幂等）后按排序重新编号                 |
| 正则清洗 `regex` | 套用预设/自定义正则模板（`applyRegexRules`，非法规则跳过）后叠加序号前缀 |
| AI 命名 `ai`     | AI 返回词干（剥离可能带回的前缀）后叠加序号前缀；支持对单条重新生成      |
| 仅改扩展名 `ext` | 词干不动，仅把扩展名统一为 `.mp4`                                        |

### 序号体系（`shared/rename-rules.mjs`）

- `SeqOptions`：`sortBy`（标题/大小，数字感知排序 `compareTitles`）、`order`（正/倒序）、`digits`（补零位数）、`separator`（分隔符）、**`start`（起始序号，1–9999，默认 1）**。
- 起始序号用于续批场景：已有 `01–50` 的批次，新数据从 51 起编。`buildSequenceStems` / `withSequencePrefix` 均接受 `start`。
- `stripSeqPrefix`：连续剥离 `01.`、`01.02.`、`03 - `、`003_`、`0001.` 等叠层前缀；**保护年份**（`2024 演唱会` 不被误剥）。

### 校验与执行

- `validateStems`：非法字符、空名、超长（>200）、重名（大小写不敏感）逐条标红，存在错误禁止执行。
- 真实容器探测（`rename:probe` → ffprobe）：识别「伪 MP4」，配合仅改扩展名模式使用。
- 执行（`modules/rename/execute.mjs`）：**两段式改名**（先临时名后目标名）规避交换冲突；封面（`posterRel`）与视频联动改名；产出 `RenameReport` 并写日志。

### AI 命名（`modules/rename/ai.mjs`）

- OpenAI 兼容端点（`chat/completions`），多平台配置（预设 openrouter / deepseek / aicodemirror + 自定义），**token 按平台独立持久化**，模型下拉可切换。
- 批处理（`AI_BATCH_SIZE` 一批多文件）、prompt 模板变量 `{{parentFolder}} {{fileName}} {{extension}}`（`buildPrompt`）、会话级缓存（`useCache`）、指数退避重试与超时（`fetchWithRetry`）。
- 响应解析 `extractJsonArray` 容忍模型输出包裹文本；失败批次保留原名不阻塞整体。
- AI 生成过程接入全局进度条（按批次上报）。

## 四、封面管理（PosterPage）

**能力**：批量为视频生成/更换封面，卡片网格展示，支持逐片精选帧与批量保存。

### 流程

1. **列表**（`poster:list` → `listPosterVideos`）：视频及其现存 poster。
2. **候选帧**（`poster:capture` → `captureCandidates`）：对每个视频取多张候选帧——时间均布采样（`buildFrameTimestamps`）+ **场景切分检测**（`detectSceneCuts`，ffmpeg scdet，挑画面变化大的帧），帧存临时目录（`framesRoot`），经 TaskCenter 并发截取。
3. **精选**（`PosterDetail` 组件）：逐片查看候选帧大图；支持输入任意秒数定点补截（`poster:capture-at` → `captureAt`）；选定帧作为该视频候选封面。
4. **保存**（`poster:save` / `poster:save-batch`）：选中帧复制为 `<视频基名>-poster.jpg`（sharp 转 JPG），同路径覆盖写并删除旧 poster；批量保存先经 `computePendingSaves` 算出待保存集（跳过未变更项），二次确认后执行。
5. **缓存处理**：协议层图片 `no-store` + 渲染端 URL 版本参数，保证覆盖写后界面立即显示新图；`cleanupFrames` 清理临时帧。

## 五、NFO 归档（NfoPage）

**能力**：把散乱视频按「一片一目录」归档，生成 Emby/Jellyfin 兼容的 `.nfo` 元数据。

- **计划**（`createNfoPlan`）：每个视频 → 目标目录（以词干命名，相对工作区根），关联 poster 一并纳入；目标目录已存在且非空标记 `conflict`；从目录结构推断默认演员名 `actorDefault`。
- **执行**（`executeNfoPlan`）：建目录（`ensureDir`）→ 移动视频与 poster → 写入 `movie.nfo`（`renderNfoXml`：`title`/`poster`/`actor`，XML 转义 `escapeXml`）→ 清理空目录。冲突项在 UI 提示由用户确认策略。
- 产出 `NfoReport`（归档数、失败项、耗时）并写日志。

---

## 六、视频去重（DedupePage）

**能力**：找出内容完全相同的重复视频，按组展示，勾选删除。

- **判定**（`modules/dedupe/dedupe.mjs` + `core/file-hash.mjs`）：先按文件大小分组，同大小再计算**采样哈希**（`hashFileSample`，头/中/尾采样 MD5，避免全量读大文件），同哈希归为重复组。
- **删除**：每组默认保留第一个（可按目录/大小排序后人工勾选），确认后经 TaskCenter 批量 `permanentDelete`，产出删除报告并写日志；UI 实时显示勾选可释放的体积。

## 七、媒体库（LibraryPage）

**能力**：只读浏览工作区——卡片网格（封面 + 标题 + 大小）、搜索过滤、点击播放。

- 数据源复用 `poster:list`；封面缺失显示占位。
- 播放经 `VideoModal`：`media://` 流式加载（支持 Range 拖动），**记忆播放进度**，再次打开续播。

---

## 八、设置（SettingsPage）

持久化于 `userData/settings.json`（`core/settings.mjs`，`normalizeSettings` 负责旧版本配置迁移）：

- **并发线程数**：1–20，默认 5（`clampConcurrency`），作用于除视频合并外的全部批量任务；
- **AI 平台**：多平台配置（预设 + 自定义），各自独立保存 baseUrl / token / 模型列表 / 当前模型，切换平台不清除 token；
- **Prompt 模板**：AI 命名模板，支持 `{{parentFolder}} {{fileName}} {{extension}}`；
- **正则模板**：重命名清洗规则预设（名称 + pattern + replacement + flags），可增删。

设置输入做防抖保存；渲染端改动即写即读。

## 基础设施

### TaskCenter（`core/task-center.mjs`）

统一并发调度：`run({ taskId, label, items, worker, concurrency })` 逐项派发，`worker` 收 `AbortSignal`；`cancel(taskId)` 停止派发并通知在途。每项产出 `TaskEvent`，主进程 120ms 节流后广播 `tasks:event`；渲染端 `TaskProgress`（右下角全局进度条）与 `TaskCenter`（任务抽屉，历史任务列表）订阅。

### 页面状态与自动重扫（`useWorkspaceSync`）

- 8 个页面常驻挂载，切换仅显隐，状态（扫描结果、报告、排序、编辑内容）完整保留；每页独立 `ErrorBoundary` 隔离崩溃。
- 页面变为可见或工作区切换时，对比 `computeFingerprint(root)`（递归文件 `相对路径:大小:mtime` 排序后的 MD5，隐藏项不计）：
  - 指纹不变 → 直接展示缓存结果；
  - 指纹变化 → 自动调用该页扫描函数；
  - 指纹计算失败（目录被删等）→ 静默保留原状。

### media:// 协议（`src/main/index.ts`）

渲染端访问本地媒体的唯一通道。只允许已选工作区与截帧临时目录（越界 403）；透传 Range（视频进度条）；图片强制 `Cache-Control: no-store`。渲染端经 `mediaUrl()` 生成 URL。

### 操作日志（`core/op-log.mjs`）

清理 / 重命名 / NFO 归档 / 合并删源 / 去重删除 完成后写 JSON（含模块、时间、参数、报告、一句话摘要）到 `userData/op-logs/`；`OpLogPanel` 倒序展示，`op-logs:reveal` 在系统文件管理器中定位。写日志失败不影响主流程。

### 文件操作（`core/fs-ops.mjs`）

全部写操作唯一入口：`permanentDelete`、`ensureUniquePath`（重名 ` (n)`）、`moveWithCollision`、`renameWithCollision`、`directRename`、`writeTextFile`、`removeEmptyDirs`（含垃圾文件识别）、`ensureDir`、`diskFreeBytes`。

### 媒体探测（`core/probe.mjs`）

`probeMedia` 解析 ffprobe JSON 为 `MediaInfo`（容器/时长/分辨率/方向/编码/帧率/像素格式/音频参数）；`probeMediaCached` 按 路径+mtime 缓存，重复扫描免探测。
